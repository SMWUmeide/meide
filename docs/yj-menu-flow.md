# yj 메뉴판 촬영·주문 흐름 구현과 Figma 차이

기준: `src`의 DESIGN-yj.md 전체(충돌 시 11–13절 우선), ROUTES-yj.md ② 및 홈 진입.
Figma Page 2의 홈 4개와 요청한 17개 화면을 각각 `get_design_context`와 반환 스크린샷으로 확인했다.

## 실행과 목업 조건

`npm run dev` → 로컬 앱. 실제 앱 루트는 React 화면을 사용한다. 기존 Worker의 `/` 정적 HTML 우회를 제거했다.

- 기본 장바구니는 비어 있다. 메뉴를 직접 담아 22 → 02를 확인할 수 있다.
- `/menu?fixture=shared`, `/cart?fixture=shared`, `/order?fixture=shared`, `/receipt?fixture=shared`: Figma의 내 메뉴 1개 + 김미영님 메뉴 2개를 미리 담은 검증용 진입 주소.
- `/capture?fixture=photos`: 목업 사진 2장. 첫 사진은 읽힘, 둘째는 흐림으로 정해져 있다.
- `/capture?camera=denied`: 41. 설정 버튼은 허용 후 08 복귀를 모사한다. 실제 기기 설정이나 카메라를 호출하지 않는다.
- `?analysis=success` 또는 `?analysis=partial`: 분석 결과를 고정하는 검증용 조건. 일반 조건에서는 사진 1장은 성공, 2번째 이후 새 목업 사진은 일부 실패한다. 실패 사진을 다시 찍으면 교체되어 성공한다.
- 앨범은 브라우저 파일 선택을 사용한다. 실제 업로드는 없으며, 선택 사진·인식 상태만 IndexedDB에 임시 보관한다. 장바구니·직원 답변·주문 상태는 현재 실행 메모리에만 있다. 계정 저장 API는 연결하지 않았다.
- 분석, 식당 검색, 동행자 연결, 환율은 모두 목업. 식당명·주소 검색도 제공된 목록 안에서만 동작한다. 읽은 메뉴만 보기에서는 수프 4개만 남는다.
- 주문 요청 목업 번역: `치즈 빼고 주세요`, `우유 빼고 주세요`, `맵지 않게 해주세요`, `물 주세요`. 나머지는 한국어 원문을 유지하고 번역되지 않았음을 표시한다.
- TTS는 기기의 로컬 이탈리아어 음성만 사용한다. 지원하지 않으면 안내와 크게 보여주기를 이용한다. 외부 음성·분석·번역·지도 API는 호출하지 않는다.

## 공통 컴포넌트

`components/yj/ui.tsx`에서 DESIGN-yj.md 12-10의 컴포넌트를 먼저 정의했다. 화면은 이 컴포넌트와 `lib/yj/model.ts`의 동일한 목업 데이터·계산 함수를 조합한다. `SplitTalkLayout`, `Toggle`, `DangerButton`, `RatingKorean`은 공통 규격만 제공하며 범위 밖 화면을 추가하지 않았다.

홈·주문 내역·둘러보기·MY 탭은 원본처럼 보이되, 이번 범위 밖 탭과 여행지·동행자·평가·15/16 대화 화면의 액션은 연결하지 않고 비활성 처리했다. 다른 목적지로 임의 연결하지 않았다. 18의 문장 확대는 질문을 유지한 17 형식이며 닫으면 18로 돌아온다.

## 화면별 Figma 차이

공통으로 Noto Sans KR을 로컬 파일로 사용했다. 웹 브라우저의 글꼴 렌더링 때문에 자간·행 높이·줄바꿈이 Figma와 수 px 차이 날 수 있다. 390 × 844(홈 402 × 874)를 기준으로 만들고, 작은 기기에서는 스크롤과 safe area를 적용한다. 긴 상세·영수증은 원본을 축소하지 않고 본문을 스크롤한다. 고정 하단 영역이 마지막 항목을 가리지 않도록 본문과 분리했다.

| 화면 | Figma와 다른 점 및 이유 |
| --- | --- |
| 홈 4종 | 시스템 상태바는 웹 목업 표기라 통신·Wi-Fi·배터리 모양이 원본 iOS 컴포넌트와 다르다. 현지 시각(Europe/Rome)에 따라 4종을 선택한다. 평가 전에는 시간대와 무관하게 촬영 안내, 주문 후에는 평가 알림을 표시한다(13절 우선). 범위 밖 탭·위치·아바타·평가 이동은 비활성. 오브는 Figma 원본 SVG다. |
| 08 촬영 | 실제 카메라 대신 원본과 같은 편집 가능한 메뉴판 종이 목업을 표시한다. 플래시는 비활성. 종이의 글자 행간·회전 경계에 수 px 차이가 있다. 셔터·앨범 아이콘은 원본 자산을 쓴다. |
| 09 촬영 완료 | 고정 2장 대신 실제 추가한 수를 표시한다. 사진 묶음은 현재 마지막 사진을 사용한다. 종이의 행간·스택 간격에 미세한 차이가 있다. |
| 10 사진 펼쳐보기 | 실제 수량에 따라 행이 늘어나고 본문만 스크롤한다. 삭제 터치 영역을 36px로 확보해 원본의 32px 원보다 크다. 사진 없는 상태에서도 더 찍기에 접근할 수 있다. |
| 11 사진 확대 | 고정 1/2와 두 점 대신 실제 인덱스·전체 수·점을 표시한다. 종이 텍스트 행간 때문에 원본보다 하단 문구가 약간 낮다. 삭제·교체는 현재 사진에 적용한다. |
| 39 인식 중 | **12-4절을 우선해 Figma에 남아 있는 오브를 뺐다.** 상단 절반 그라디언트와 단계 카드는 유지했다. 14개 대신 목업 7개(일부 결과 4개), 실제 사진 수를 표시한다. 타이머로 단계를 진행하며 분석 서비스는 없다. |
| 40 인식 실패 | 고정 2번째 사진 대신 실패한 사진 인덱스를 표시한다. 사진 수가 늘면 확인 영역도 늘어난다. 완료 배지는 허용된 공통 색으로 적용해 원본의 별도 연녹색과 다르다. |
| 13 식당 확인 | 도형 지도와 식당 정보는 목업이다. 지도 도형의 블록·도로 위치에 미세한 차이가 있으며 실제 OSM 요청은 하지 않는다. 위치·마커 아이콘은 원본 자산. |
| 14 식당 선택 | 원본 4개 목록을 검색·선택할 수 있다. 결과 없음은 같은 화면의 짧은 안내로 표시한다. 실제 위치나 식당 검색은 연결하지 않았다. |
| 01 메뉴 선택 | 잘려 있던 첫 카드 +와 수량 버튼을 사진 오른쪽 아래에 배치했다. 기본은 빈 장바구니이며 shared fixture에서 원본의 3개·동행자 틴트를 볼 수 있다. 숫자는 담은 수를 반영한다. 카드·칩의 줄바꿈과 섹션 간격에 수 px 차이가 있다. |
| 06-2 메뉴 상세 | 호박 수프는 원본 사진·문구·AI/확인/추정 구성을 유지했다. 다른 메뉴는 같은 공통 틀에 목업 정보를 넣는다. 직원 답을 기록하면 추정 카드에 답변을 추가한다. 본문 높이는 글자 줄바꿈에 따라 바뀐다. |
| 18 재료 확인 | 선택한 메뉴명을 표시하고 답변 칩에 선택 상태를 표시한다. 원본의 무선택 상태와 달라질 수 있다. 실시간 대화 버튼은 범위 밖이므로 비활성. TTS 지원 여부는 기기에 따라 다르다. |
| 02 장바구니 | 잘못된 동행자 소계 EUR 22.00을 EUR 30.80으로 수정했다(shared fixture, 팁 포함). 수량·팁·음식·전체 합계를 같은 데이터로 계산한다. 시트 높이는 텍스트에 맞춰 원본보다 약 10px 차이가 날 수 있다. |
| 22 빈 장바구니 | 오브 없이 제목·안내·버튼을 유지한다. 실제 수량이 0일 때 표시된다. 글꼴 렌더링 외 별도 의도적 시각 변경은 없다. |
| 03 주문 문장 | 문장은 현재 수량·요청사항에 따라 길어져 카드가 가변 높이다. 요청사항은 실제 textarea라 크기 조절 핸들이 보일 수 있다. 목업에서 모르는 요청은 원문과 안내가 추가된다. 직원 재질문 버튼은 범위 밖이므로 비활성. |
| 17 크게 보여주기 | 03과 같은 데이터의 문장을 사용해 Figma의 별도 축약 문장과 다르다. 18에서 열면 주문 문장 대신 재료 질문을 표시한다. 문장이 길면 본문 스크롤. |
| 04 영수증 | 메뉴·수량·팁·식당·날짜는 현재 목업 주문을 반영한다. 음식+코페르토+선택 팁으로 합계를 계산하고 물은 제외한다. 환율 1,499원에서 반올림하므로 원본 원화 합계와 1원 차이(shared: 70,153원 vs 70,154원)가 난다. 상단바 고정·본문 스크롤로 1,155px 원본을 기기 높이 안에서 읽는다. |
| 41 카메라 권한 | 원본 안내·아이콘·설정 예시를 유지한다. 설정 허용은 목업 상태만 바꾸며 실제 OS 설정을 열지 않는다. 실제 앨범 선택 후에는 09로 간다. 안내 카드의 행간·높이에 수 px 차이가 있다. |

## 검증

- `npm run build`: 성공.
- 변경한 React/TypeScript 파일 ESLint: 성공.
- `node --test scripts/yj-flow.test.mjs`: 5개 성공(금액·소유자·수량 0·문장·현지 시각·같은 주소의 상태).
- Chrome 실제 클릭: 홈 → 08 → 09 → 10 → 11 → 39 → 40 → 13 → 14 → 01 → 22 → 01 → 06-2 → 18 → 질문 확대 → 상세 복귀 → 담기 → 02 → 03 → 17 → 04 → 홈 성공.
- 추가 검증: 사진 삭제·교체·재인식 성공, 분석 취소, 권한 안내·허용 복귀, 앨범 선택·새로고침 후 사진 복구, 수량 0 빈 상태, 팁 켜기/끄기, 동행자 편집 불가.
- 320·390·402·768px에서 9개 주요 화면씩 총 36개 렌더: 가로 넘침 없음, 누락 이미지 없음. 사용한 원본 자산 48개 모두 로컬 비어 있지 않은 파일이며 렌더 시 로딩 확인. 외부 요청 없음.
- 전체 `tsc --noEmit`에는 기존 `lib/cloud-api.ts`의 콜백 타입, `lib/cloud-cities.ts`의 암시적 any 오류가 남아 있다. 이번 범위 밖 코드이므로 변경하지 않았다. Worker에서 옛 정적 홈 import를 제거하여 기존 `index.html?raw` 오류는 해소했다.
