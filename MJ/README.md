# Meide Mobile

## Google Play 심사용 메뉴판 분석과 주변 식당 검색

- 출시용 Android 앱의 **내 주변 식당 찾기 → Google Play 심사 코드 입력**에서 심사 전용 코드를 입력하면 피렌체의 예시 위치 주변을 실제 Google Places 데이터로 검색해요. 일반 테스트 명단에 등록할 필요 없이 홈으로 돌아가 메뉴판을 촬영하거나 이미지를 선택해 분석할 수도 있어요. 앱을 완전히 종료하면 코드를 다시 입력해요.
- 운영 배포 시 32바이트 이상의 난수로 만든 URL 안전 코드를 사용하고, Cloud Run에 `PLAY_REVIEW_CODE_SHA256`으로 코드의 소문자 SHA-256 값만 넣어요. 원문은 Play Console의 앱 접근 정보에만 제공하고 저장소·앱 번들·요청 로그에 기록하지 않아요.
- 심사 검색과 메뉴판 분석은 일반 테스트 사용량과 각각 별도로 집계해요. 한국 시간 기준 각 기능을 기기마다 하루 2회, 심사 전체에서 하루 8회까지 이용할 수 있어요.
- 배포 후 새 빌드를 설치한 기기에서 심사 코드, 메뉴 사진 분석, 주변 식당 검색과 지도 또는 목록 표시를 확인한 다음 심사 접근 안내를 저장해요.

기존 `apps/hanip-android`와 독립적인 새 React Native / Expo / TypeScript 앱입니다.
기존 앱 코드·서버·계정·사용자 저장 데이터를 가져오지 않습니다.

- 식당 확인 → Google Places가 돌려준 공식 웹사이트에서 메뉴 찾기 → 웹 메뉴 한국어 번역 순서입니다. 웹사이트가 없거나 메뉴를 찾지 못하거나 사이트 접근/읽기에 실패하면, 보관한 촬영 원문으로 자동 진행합니다. 식당명 직접 입력 단계는 추가하지 않았습니다.
- HTML 메뉴, 구조화된 메뉴 정보(JSON-LD), 메뉴 PDF, 메뉴로 식별된 PNG/JPEG를 지원합니다. PDF는 텍스트를 먼저 읽고 필요한 경우 이미지를 만들어 기존 Google Vision으로 읽습니다. 가격·통화·원문을 유지하고, 결과에 가져온 웹 메뉴의 원본 링크를 제공합니다. 한국식 AI 음식 설명은 아직 구현하지 않았습니다.
- 한 번에 웹 문서 최대 4개, HTTP 요청 최대 12개, 각 문서 3MB, 사이트 3곳, 웹 메뉴 OCR 최대 2회, 탐색 24초입니다. PDF는 앞 2쪽, 번역은 최대 5,000자를 처리하며 일부만 가져오면 화면에 표시합니다. 자바스크립트 실행이 필요한 사이트나 차단된 사이트, 여러 메뉴가 명시되어 모호한 일부 사례는 촬영 원문으로 넘어갑니다. 모든 지점·시즌 메뉴를 자동으로 구분하는 기능은 아닙니다.
- 공개 HTTPS 주소만 허용하고 매 요청의 DNS 주소와 이동 주소를 검사합니다. 내부 네트워크/메타데이터 주소, 쿠키·로그인, 접근 차단 우회는 사용하지 않습니다. robots.txt의 접근 제한을 따르며, 식당 사이트로 Google 비밀 키를 보내지 않습니다. 웹 메뉴 본문은 Firestore에 저장하지 않습니다.
- 확인된 식당 후보만 상세 조회할 수 있고, 기존 촬영 요청의 상세 단계에서 실행합니다. 번역은 웹/사진 중 선택된 원문에 한 번만 수행합니다. 기존 1인 하루 2회·총 600회·메뉴당 $0.20 예약 한도를 유지하며, 새 웹 메뉴 OCR도 이 예약 안에서 최대 2회로 제한합니다. 앱의 예약 한도는 Google 결제 계정 전체의 지출 차단 설정이 아닙니다.

### 메뉴판 기능 진행 기준 (2026-11-16)

현재 단계는 **촬영/갤러리 → Google OCR → 식당명 후보 자동 추출 → Google 식당 검색 → 식당 확인 → 웹 메뉴 우선 읽기(실패하면 촬영 원문) → 한국어 번역**입니다.
홈의 노란 촬영 버튼 → 갤러리 사진 선택 또는 촬영 후 썸네일 → 전송 동의 → 메뉴판 번역하기 순서입니다.
인식한 원문은 번역 실패 시에도 유지합니다. 5,000자를 넘으면 원문을 직접 줄인 후 번역할 수 있습니다.
식당 확인 화면은 Figma `894:5527`의 배치·서체·아이콘을 사용하고 실제 Google 데이터로 채웁니다. 현재 위치를 쓰지 않으므로 반경/거리/도보 시간은 임의로 표시하지 않습니다.
식당명 추출은 OCR의 상단 제목·식당 접두어 규칙을 사용하는 보수적인 후보 판별입니다. 모든 메뉴판의 식당명을 식별하지는 못합니다.
식당명이 없거나 후보가 없거나 검색이 실패하면 **직접 이름을 입력하는 단계 없이** 촬영한 글자의 번역을 계속합니다. 후보가 모두 틀리면 식당 연결 없이 계속할 수 있습니다.
확인한 식당의 공식 웹사이트에서 웹 메뉴를 우선 가져오고, 가져오지 못하면 촬영 원문을 사용합니다. 한국식 음식 설명은 후속 작업입니다. 식당 사진·지도·주소와 웹 메뉴는 앱 세션에만 보관하며, 사진 출처와 웹 메뉴 원본 링크를 표시합니다.
현재 결과는 한국어 번역이며 음식 설명이나 알레르기 판정으로 취급하면 안 됩니다.

1. 촬영하거나 갤러리에서 선택한 사진의 글자를 읽습니다.

## GPT 메뉴 해석 연결 (2026-11-14)

사용자 후속 요청에 따라 OpenAI Responses API 연결 경로를 추가했습니다. 앞의 ML Kit 계획과 별개이며, ML Kit 네이티브 모듈은 아직 구현하지 않았습니다. 현재 경로는 **사진 → 우리 서버 → GPT 이미지 해석 → 한국어 메뉴 카드**입니다.

### 현재 동작

- 촬영 또는 갤러리 선택 → 우하단 사진 확인 → 사진 전송 동의 → `메뉴 해석하기`.
- 원문 요리명, 한국어명, 원문 가격, 설명, 한국 음식과의 비교, 명시 재료/추정 재료를 구분합니다. 원문 가격은 모델에 보존을 지시하지만 독립 OCR 검증은 아직 없어 실제 가격 정확도를 보장하지 않습니다.
- 사진별 한 번의 요청 ID를 사용하고 결과는 앱 세션에 보관합니다. 삭제/앱 재시작 시 사라집니다. 실패 후 같은 사진 자동 재시도는 하지 않으며 불확실한 과금을 피하기 위해 서버가 중복 요청을 거부합니다.
- 사진은 한 번에 한 장, JPEG/PNG 최대 4MB입니다. 서버에 사진이나 해석 결과를 파일로 저장하지 않습니다. OpenAI 요청은 `store:false`이며 이것이 OpenAI의 모든 로그 보관을 없앤다는 뜻은 아닙니다. https://developers.openai.com/api/docs/guides/your-data
- API 키 없음, 활성화 스위치 꺼짐, 사용 허용액 0, 만료일 미설정/경과 시 실제 OpenAI 호출은 차단합니다. 현재 활성화하지 않았고 유료 호출도 하지 않았습니다.

### 연결 순서

1. https://platform.openai.com/settings/organization/billing/overview 에서 **API 조직**의 크레딧 잔액·만료일·결제 설정을 확인합니다. ChatGPT 구독만으로 무제한 무료 API가 제공되는 것은 아닙니다. 일부 구독의 무료 크레딧 혜택은 https://developers.openai.com/api/docs/guides/chatgpt-api-credits 에서 확인합니다. 무료 사용만 원하면 결제/자동충전 설정을 켜지 않습니다.
2. https://platform.openai.com/api-keys 에서 이 앱 전용 프로젝트 키를 만듭니다. 키는 채팅·Figma·앱 코드에 붙여 넣지 않습니다.
3. `server/.env.example`을 `server/.env.local`로 복사하고 그 파일의 `OPENAI_API_KEY=` 뒤에 키를 저장합니다. `.env.local` 파일들은 Git에서 제외됩니다. 서버가 시작할 때 이 파일을 읽습니다. `EXPO_PUBLIC_` 접두사 변수에 키를 넣으면 앱에 노출되므로 금지합니다.
4. 크레딧/허용 예산을 확인한 뒤에만 `MENU_AI_ENABLED=true`, `MENU_AI_TOTAL_ALLOWANCE_USD`, `MENU_AI_ALLOWANCE_EXPIRES_AT`(예: ISO UTC 시각), `MENU_AI_ALLOWED_PROFILE_IDS`를 설정합니다. 만료일은 실제 무료 크레딧 만료보다 먼저, 허용액은 해당 앱에 배정 가능한 잔액보다 작게 설정해야 합니다. 다른 앱이 같은 조직 크레딧을 쓰는 경우 그 사용량을 이 서버가 알 수 없습니다. 허용할 프로필 ID는 로컬 초대 레지스트리의 id 또는 기기 저장 프로필의 profileId이며 token은 복사하지 않습니다.
5. `sh scripts/dev.sh run preview`로 서버를 재시작합니다. 로컬 웹은 같은 서버를 사용합니다. Android 설치 앱은 공개 HTTPS 서버와 `EXPO_PUBLIC_COMPANION_API_URL` 설정이 추가로 필요합니다.
6. 허용된 계정에서 메뉴 사진 한 장으로 실제 응답, 정확도, API 사용량을 확인합니다. 현재 외부 키/크레딧이 없으므로 이 실호출 검증은 미완료입니다.

### 사용 한도와 운영 범위

고정 모델 `gpt-5.4-mini-2026-03-17`, 최대 출력 4,000토큰, 도구 호출·자동 재시도 없음. 현재 가격 기준 모델의 전체 문맥 상한까지 고려해 요청마다 **$0.35를 보수적으로 사용 허용액에서 차감**합니다. 실제 청구액이 $0.35라는 뜻이 아닙니다. 실제 청구액보다 일찍 중단하는 안전 측 구현이며, 실패/시간 초과도 환원하지 않습니다. 사용자당 UTC 기준 하루 3회/월 20회. 전체 허용액은 자동으로 월 초기화하지 않습니다.

장부 `.local-data/menu-ai-usage.json`을 동기적으로 먼저 기록한 후 외부 호출합니다. **단일 서버 프로세스 + 영속 디스크 + 허용 계정 목록** 조건의 비공개 테스트용입니다. 장부 삭제·복제 또는 서버 여러 대 실행 시 한도 보호를 보장할 수 없습니다. 공개 출시 전에는 트랜잭션을 지원하는 DB의 공통 장부, 계정 인증/남용 방지, 운영 모니터링으로 교체해야 합니다. OpenAI 잔액을 자동 조회하지 않으며 무료 크레딧만 사용하는 결제 모드를 API 요청에서 강제할 수 없습니다. 이 장부는 다른 앱·키 사용이나 공급자 요금 변경까지 막는 결제 보증이 아닙니다.

선불 결제도 차단 지연으로 초과 사용이 기록될 수 있습니다: https://help.openai.com/en/articles/8264644-setting-up-and-managing-prepaid-api-billing

팀원 앱의 촬영 화면에서 사진을 1~6장 고르고 분석에 동의하면 기존 meide 메뉴 분석 서버로 보내요. 메뉴별 원어·한국어 이름과 EUR 가격을 확인하고, 담기·수량 변경·주문 문장을 사용할 수 있어요. 분석 서버와 Google에 사진이 전송돼요. 가격을 읽지 못한 항목은 제외해요. 메뉴 사진이 검증되지 않으면 준비 중으로 표시해요.

장바구니에서 동반인 초대 링크를 보내면 같은 점검 앱을 설치한 사용자가 공유 방에 참여할 수 있어요. 메뉴 선택과 수량은 기존 공유 서버에 저장되며, 본인 메뉴만 수정할 수 있어요. 연결이 끊긴 경우 10초 간격으로 다시 확인해요. 공유 방은 24시간 후 만료돼요. 식사 인원과 선택 팁은 현재 각 기기에서만 계산하므로 동반인과 자동 동기화되지 않아요. 초대 링크와 카메라의 실제 Android 기기 동작은 별도 확인이 필요해요.

점검 빌드의 앱 ID는 `app.meide.preview`예요. 공유 기능 빌드에는 `EXPO_PUBLIC_SUPABASE_URL`과 `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY`가 필요해요. 공개 가능한 클라이언트 키만 앱에 포함하고 서버 비밀 키는 사용하지 않아요. 메뉴 분석 주소는 `EXPO_PUBLIC_MEIDE_API_URL`로 지정할 수 있으며 미지정 시 기존 meide 분석 서버를 사용해요. 점검용 Android 서명은 Google Play 제출에 사용할 수 없어요.
