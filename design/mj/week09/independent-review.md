## 판정 기준과 범위

충족은 제공 증거가 해당 기준을 입증한 경우, 부분은 개선됐지만 위반 또는 중요한 미검증 범위가 남은 경우, 미충족은 직접적인 위반이 확인된 경우다. 정적 캡처에서 화면 밖 콘텐츠가 보이지 않는다는 이유만으로 삭제 또는 가림으로 단정하지 않는다. DOM audit의 transparent 배경은 실제 최종 배경색이 아니므로 합성색을 임의 추정하지 않는다.

## 항목별 근거

### 1. 색상·대비

Before 홈/장바구니의 회색 #92939A는 흰 바탕에서도 3.060:1이다. 메뉴 원문 #888888은 3.545:1, 환산 #999B9F는 2.784:1이며, 주황 배지의 흰 글자는 2.645:1로 4.5:1을 못 채운다. before 메뉴 캡처에는 파란 동반자 배지·아바타가 남아 D11에도 맞지 않는다.

After DOM에서 주요 보조 글자는 #62626C로 교정됐고 메뉴 배지는 검정 글자, 동반자 표시는 중립색과 이름을 사용한다. 캡처에서도 읽기 개선을 확인한다. 메뉴·장바구니는 흰 바탕, 검정 CTA를 유지한다. 홈은 피치/핑크와 흰색으로 이어지는 배경을 유지한다.

그러나 Light secondary와 gradient-end 조합은 **3.757:1**로 D03의 “gradient 바탕에서 4.5:1 이상” 토큰 조건을 충족하지 못한다. 홈의 실제 secondary 텍스트는 흰 카드·아래쪽 흰 영역에 놓여 있어 그 숫자를 곧바로 실제 홈 텍스트 실패로 단정할 수 없다. 현재 합성 그라데이션 위 모든 텍스트의 좌표별 배경 샘플이 없으므로 홈은 부분 판정이다. 부모 수정 시 토큰을 어둡게 하거나 보조 글자가 놓이는 면을 명시하고 실측할 것.

직접 계산은 sRGB 채널 c를 0~1로 정규화한 뒤 c≤0.04045이면 c/12.92, 그 외 ((c+0.055)/1.055)^2.4를 적용했다. L=0.2126R+0.7152G+0.0722B, 대비=(밝은 L+0.05)/(어두운 L+0.05). HSL 명도 차이를 사용하지 않았다.

### 2. 타이포그래피

Before 홈에는 10/11/13/15px, 메뉴에는 10/11/15/17px, 장바구니에는 10/11/13/15/17/22/24px가 있어 5단계 규칙에서 벗어난다. 캡처에서도 원문·환산·하단 내비게이션이 특히 작다.

After 홈의 audit 표본은 모두 12/14/16/18/26px 및 대응 행간 18/21/24/27/39px로 정리됐다. 다만 audit에 fontFamily/fontWeight가 없어 Noto Sans KR의 실제 로드·모든 굵기를 확정하지 못하므로 전체 Text Style 판정은 부분이다.

**확정 잔여 위반:** after 메뉴 `.avatar` 2개는 12px/21px로 label-sm의 18px 행간과 다르다. after 장바구니 `.cart-owner-avatar` 2개는 12px/24px, 팁 옵션 4개는 12px/21px, `−` 3개는 18px/18px로 규정 행간과 다르다. override의 `.stepper button`은 크기만 h2로 바꾸고 행간을 교정하지 않았다. 네이티브 select의 option은 플랫폼 영향이 있을 수 있으므로 실제 표시 상태도 재확인할 것. 기호·아바타를 예외로 둘 의도라면 문서에 예외를 명시해야 한다.

### 3. 간격·그리드

캡처의 2열·화면 여백 구조는 before부터 존재한다. Before audit에는 padding/gap의 계산값이 없어 전부 위반이라고 추측하지 않았다. After CSS는 좌우20, 카드16, 2열12, minmax(0,1fr), 원문 줄바꿈을 정의하며 캡처도 일치하는 방향이다. 그러나 audit에는 실제 padding/gap/좌표가 없고 390px 폭만 있다. 360/440 검수가 요구되므로 전부 부분이다.

엄격한 4px 격자에서 `.cart-items { padding:2px }`는 문서에 없는 예외다. 포커스 테두리 확보 목적이라면 예외 규칙을 추가하거나 토큰 격자로 교정할 것. 단지 CSS 값을 바꿨다는 사실을 실제 모든 간격 검증으로 간주하지 않는다.

### 4. 라운딩·그림자

After 캡처는 홈 카메라 특유의 유리 효과, 흰 quick card, 사진 라운딩, 홈 순위의 별도 흰 박스 없는 구조를 유지한다. CSS는 사진12, 버튼16, 큰 카드24 및 card/floating 그림자, 카메라177×120/51 예외를 명시한다. 다만 audit에 실제 radius/boxShadow/크기 계산값이 없고 base CSS와 합성된 결과의 수치까지 확인할 수 없다. Before도 외관은 일부 유사하나 규정값 일치 증거가 없으므로 부분이다. 정적 PNG만으로 정확한 그림자 blur/alpha를 인증하지 않는다.

### 5. 상태·접근성

Before smallTargets는 홈1개(위치165×39), 메뉴7개(뒤로36×36, 초대약34×21, 추가36×36 등), 장바구니8개(뒤로36×36, 수량40×40 6개, 팁 높이40)다. After audit에서는 세 화면 모두 smallTargets가 빈 배열로 개선된다. 캡처에서도 추가·수량 버튼이 커진다.

After CSS에 focus-visible, disabled, primary:active, reduced-motion이 정의돼 있다. 하지만 정적 기본 화면·현재 audit는 실제 Tab 순서, 접근 가능한 이름, disabled 속성, 로딩 중 중복제출 차단, 오류/빈 상태, reduced-motion 실행을 보여주지 않는다. 체크박스는 min44 선택자에서 제외되고 label 최소높이만 있으므로 실제 label의 클릭영역도 별도 확인해야 한다. smallTargets 수집기의 대상·가시성 조건도 제공 JSON에는 없다. 따라서 “접근성 충족”으로 확대 판정하지 않는다.

### 6. 콘텐츠·스크롤·기능보존

세 화면 모두 before/after audit의 390px overflow=0이다. 메뉴 캡처는 원문·재료 배지·EUR/원화·나/동반자 표시를 보존하고 after는 긴 설명이 줄바꿈된다. 그 결과 after의 두 번째 행은 접힌 화면 아래로 더 내려간다. 이는 즉시 가림 오류가 아니며 끝까지 스크롤한 캡처가 필요하다. 홈도 두 번째 순위 일부가 하단에 보이고 이후 순위·마지막 콘텐츠 도달 증거는 없다.

장바구니는 두 소유자 이름·소계와 총액이 양쪽 캡처에 남는다. before 내부 목록 높이147/scrollHeight147,277, after139/scrollHeight139,317이며 overflow:auto다. 이는 독립 스크롤 컨테이너와 넘치는 두 번째 목록의 존재를 입증하지만, 실제 스크롤 후 제목/소계가 고정되는지·키보드 포커스·소유자 접근성 이름은 audit에 없다. CSS 주석만으로 상호작용 통과로 간주하지 않는다.

표시 총액은 €10+€25=€35, 35×1,550=54,250원으로 일치하고 총3개가 유지된다. 그러나 수량 변경·삭제, 팁5/10/15/직접 입력 계산, 메뉴 이동, 원문/API/data-* 불변은 이 증거만으로 실행 검증할 수 없다. 이번 평가는 제공된 디자인 적용 증거를 범위로 한다. 양쪽 모두 부분 판정이다.

## Figma 25개 의미 토큰 검증

제공 export를 직접 파싱하고 두 모드 alias를 Primitive 값까지 해석하여 tokens.json과 비교했다.

- 실제 총 변수55=Primitive30+Semantic25. Semantic 구성은 COLOR9/FLOAT14(타입5+간격6+반경3)/STRING2다. collection의 선언 count와 실제 개수가 일치한다.
- Light(86:1)/Dark(86:2)에서 Semantic25개 모두 값이 존재한다. 50개 값 모두 VARIABLE_ALIAS이며 존재하는 Primitive 컬렉션 변수를 가리킨다. 두 모드 해석값과 tokens.json 사이 불일치0개다. 공통 수치 Primitive 재사용은 유효하다.
- Semantic 색상9개 scopes는 FRAME_FILL/SHAPE_FILL/TEXT_FILL/STROKE_COLOR, 타입5개 FONT_SIZE, 간격6개 GAP, 반경3개 CORNER_RADIUS다. 그림자 STRING2개 scopes=[]는 effect 직접 바인딩 증거가 아니다. Primitive scopes=[]도 이 export 사실 그대로다.
- Semantic25개 모두 WEB `var(--color-* / --type-* / --space-* / --rounded-* / --shadow-*)`가 존재하고 해당 이름·역할에 맞는다.
- export에는 Text Style/Effect Style, 노드별 binding, 폰트 family/weight/line-height style 정보가 없다. 문서가 요구하는 Text Style 묶음 및 Effect Style 동일값 등록은 이 파일로 확인 불가다. 현재 원격 Figma 상태를 읽거나 수정하지 않았으므로 이 결과는 export 스냅샷에 한정한다.

## 문서 규칙이 없어 별도로 제안하는 항목

아래는 현행 규칙의 확정 위반으로 세지 않는다.

1. 확대 검수 배율·브라우저/기기·세로 높이별 기준과 통과 조건을 명시할 것. “확대 막지 않기”만으로 재배치 품질을 판정할 수 없다.
2. 비텍스트 아이콘/포커스 표시 대비 목표, 포커스 이동 순서·모달 복귀·스크린리더 이름 규칙을 추가할 것. 현재 문서는 가시 포커스만 명시한다.
3. 로딩/빈/오류 상태의 문구 예시, 타임아웃·재시도·진행 알림 방식과 캡처/행동 증거 형식을 정할 것.
4. 합성 그라데이션의 실제 텍스트 배경 샘플 지점·이미지 위 글자 합성 측정법을 명시할 것.
5. 아바타·수량 기호·네이티브 옵션의 Text Style 예외를 허용할지 결정할 것. 현행 문서에서는 위 행간을 예외로 인정할 근거가 없다.

## 부모 작업에 전달할 수정·재검증 우선순위

1. Light secondary/gradient-end의 3.757:1 조건을 해결하고 문서·tokens·Figma를 함께 맞춘 뒤 실제 합성 배경 대비를 재측정한다.
2. 메뉴 아바타 및 장바구니 아바타·수량 기호·옵션의 행간을 교정하거나 합의된 예외를 문서화한다.
3. 360/390/440 폭의 마지막 콘텐츠 도달, 장바구니 실제 독립 스크롤과 고정 제목·소계, 포커스/이름, 상태 전환 및 수량/팁 계산을 행동 증거로 보완한다.
4. Text/Effect Style 등록과 노드 바인딩은 별도 Figma 증거를 확보한다.

결론: 가독성과 터치 영역의 개선은 명확하지만 문서 전체 기준의 완전 충족으로 판정할 수 없다. 정적 증거로 확인되지 않은 실행 결과를 성공으로 기록하지 않았다.
