## 8주차

### 한 일
- 스쿼클·황금비 기반 디자인 시스템 고민 (교수님의 '황금비 적용' 피드백 + 4pt 그리드를 쓰고 싶어서 시작)
  - 피보나치 × 4: 피보나치 수(1, 2, 3, 5, 8, 13)에 4를 곱해 간격 단계를 4 / 8 / 12 / 20 / 32 / 52로 잡음 → 4의 배수를 지키면서 이웃한 단계끼리는 황금비(약 1.618)에 가까움
  - 근접성 원리 적용: 간격을 모두 1:1로 두면 제목이 위아래 어느 카드 것인지 애매함 → 카드–자기 제목 간격과 다음 묶음 간격을 약 1:1.6으로 차이 두기 (예: 12 → 20), 관계가 멀수록 한 단계씩 올라감
  - 타이포: 16pt를 기준으로 황금비를 곱하고 4pt 단위로 반올림하는 방식 검토. 다만 1.618을 그대로 쓰면 모바일에서 단계가 너무 급해져 글자가 금방 커짐
  - 스쿼클: 일반 둥근 모서리는 직선→원호에서 곡률이 갑자기 바뀌어 살짝 꺾여 보이지만, 스쿼클(초타원)은 곡률이 서서히 바뀌어(G2 연속) 더 매끄러움. Figma Corner smoothing 60%로 iOS 느낌을 냄 (1/φ ≈ 61.8%와도 거의 같음)
  - 라운드 토큰도 같은 수열로: 8 / 12 / 20 / 32 / 52 / full(버튼·칩·아바타). '바깥 R = 안쪽 R + 패딩' 규칙이 피보나치 덧셈과 맞아떨어짐 (예: R20 카드 + 패딩 8 → 안쪽 R12)
  - 레퍼런스 앱 화면을 분석해 보니, 여유 있어 보이는 디자인은 패딩이 라운드 값의 80~100% 정도였음
  - 실제 사례 조사: iOS 아이콘의 스쿼클, Figma Corner smoothing, 트위터 로고(2012)처럼 설계 의도가 확인된 사례와, 애플·펩시 로고처럼 나중에 끼워 맞췄다는 논란이 있는 사례를 구분함
- 구글 플레이 개발자 계정 생성 (meide 출시용)

### 사용한 도구
- Claude (스쿼클·황금비 원리 정리, 레퍼런스 분석)
- Figma (Corner smoothing)

### 실패한 시도와 배운 점
- 황금비는 무리수라 픽셀로 딱 떨어지지 않음 → 황금비를 직접 곱하기보다 피보나치 수를 4pt 그리드에 맞춰 쓰는 쪽이 실무에 맞음
- 타이포에 1.618을 그대로 쓰면 단계가 너무 급함 → 수학 값은 뼈대로만 쓰고 4pt 반올림과 눈으로 보정해야 함
- Corner smoothing을 켜면 같은 R이라도 덜 둥글어 보임 → 큰 카드는 라운드를 한 단계 위 값으로 올려야 의도한 둥글기가 나옴
- '황금비라서 아름답다'는 근거는 생각보다 약하고 끼워 맞춘 사례도 많음 → 근거는 확인된 사례만 들고, "수학으로 뼈대를 잡고 시각 보정으로 마무리"하는 것을 컨셉으로 설명하는 게 설득력 있음
