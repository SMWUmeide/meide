# meide

## 5주차

### 한 일
- 아이디어 2개 디벨롭: ① 한국인의 감각으로 풀어주는 유럽 미식 가이드(메뉴판 앱), ② 여행 체력 관리 도우미(예비안)
- 두 아이디어 각각 PRD → 기능명세서 → 유저플로우 → 프로토타입 제작
- 결과물은 Figma '사용자 경험 디자인 II' 페이지에 정리

### 사용한 도구
- Claude 채팅(Opus)으로 PRD·기능명세서 초안 작성, Claude Design으로 와이어프레임·프로토타입 제작

### 실패한 시도와 배운 점
- 유사 앱 emo가 거의 같은 기능을 제공한다는 걸 발견 → 메뉴 설명만으로는 차별점이 약해서 미식 가이드(먹는 법, 와인 페어링, 현지 식문화, EU 알레르기 번호)로 방향을 넓힘
- 예비안으로 워치·폰 연계 체력 앱을 구상했지만 현실성이 낮아 메뉴 번역 서비스로 결정

## 6주차

### 한 일
- 프로토타입 기능 정리
- 사용자 테스트 세션 1, 2 진행 (세션 1: 10/11 가족 3명 / 세션 2: 10/12 선생님 1명)
- 두 세션 결과를 분석해 문제점 6개와 수정 우선순위 정리

### 사용한 도구
- Claude Code
- 클로바노트로 테스트 음성 전사, Claude로 전사본 분석

### 실패한 시도와 배운 점
- 메뉴 담기(+) 버튼을 찾지 못해 핵심 과업(메뉴 선택)이 막힘 → 버튼의 크기·위치·대비가 기능 자체보다 중요하다는 걸 배움
- 사용자가 실물 메뉴판과 앱 결과를 하나씩 맞춰 보려 함 → 결과 화면에서 원본 메뉴판 위치를 알 수 있어야 한다는 근거를 얻음
- 주문 완료 후 다음 행동이 불분명했고, 결제·주문 전송이 되는 앱으로 오해하는 경우도 있었음 → 첫 화면에서 "직원에게 보여주는 방식"이라고 알려줘야 함
- 진행자가 중간에 안내를 해서 자연스러운 탐색이 일부 흐려짐 → 다음 테스트에서는 개입을 줄이고 막히는 지점을 그대로 관찰
- 카카오톡으로 메뉴판 사진을 받아 넣는 과정은 앱 문제가 아닌 테스트 환경 문제라 분리해서 해석해야 함

## 7주차

### 한 일
- 프로토타입 2차 제작(한입 유럽 v2)
  - 홈: 찜 기능, 현지 문화·대표 음식 진입점, 식문화 아티클 캐러셀 삭제
  - 촬영: 카메라 전체 화면, 촬영한 사진을 스택 → 카드 그리드로 펼쳐 확인
  - 식당 확인: '맞아요 / 아니에요(주변 식당 찾기) / 건너뛰기'로 단순화, 메뉴판 확인 단계 삭제
  - 메뉴: 2열 카드형, 원문·한글 이름·가격만 표시, 동반인이 담은 메뉴는 프로필 아이콘으로 표시
  - 장바구니·주문: 사람별 합계 표시, 주문 화면을 스크롤 없이 보이도록 조정
- 프로토타입 최종본 제작
  - 주문 완료 후 영수증 화면 추가
  - 실시간 대화 기능 추가
- 디자인 시안 제작 (Figma, `design` 브랜치 `design/yj/`에 시안 8장 업로드)
  - 홈: 시간대(이른 아침·오전·점심·저녁)에 따라 배경 색과 인사 문구가 바뀌는 4종, 가운데 구슬 형태 촬영 영역
  - 메뉴 선택: 카테고리 탭, 2열 카드형, 동반인이 담은 메뉴는 프로필 아이콘과 색 오버레이로 표시
  - 함께 담은 장바구니: 사람별 메뉴와 합계, 선택 팁 10% 포함 여부와 예상 총액
  - 주문 문장: 한글·현지어 문장, 소리·확대 아이콘, 요청사항 입력
  - 영수증 미리보기: 메뉴별 금액, 코페르토·물값 안내, 팁, 예상 합계(원화 환산)

### 사용한 도구
- Claude Code

### 실패한 시도와 배운 점
- 불필요한 단계(메뉴판 확인 화면)와 기능(찜)은 빼는 쪽이 흐름이 깔끔해짐
