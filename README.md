# meide · 한입

새 앱은 저장소 최상위의 React + TypeScript + Vite 프로젝트예요. 소스는 `src/`, 이전 앱은 `yj/`에 있어요. 홈 → 촬영 → 메뉴 고르기 → 메뉴 상세 → 장바구니를 예시 데이터로 연결했어요. 메뉴판 사진은 Vercel 서버리스 함수를 통해 Gemini로 분석해요. Google Places 사진 연결은 아직 하지 않았어요.

```sh
npm ci
npm run dev
```

Node.js 22.13 이상이 필요해요. 기본 주소는 `http://127.0.0.1:5173`이에요. 촬영 화면에서 사진을 고르거나 “예시 메뉴판으로 시작하기”를 누르면 메뉴를 확인할 수 있어요. 사진은 분석 버튼을 누를 때만 크기를 줄여 서버와 Gemini로 전송해요. 앱의 파일 저장소에는 저장하지 않아요. 새로고침하면 예시 장바구니로 돌아가요.

```sh
npm run build
npm run lint
npm test
npm run check:design
```

컴포넌트는 `src/components/index.md`의 import 경로를 사용해요. 예시 화면에는 키가 필요 없고, 실제 사진 분석에는 서버의 `GEMINI_API_KEY`가 필요해요. 개발 환경과 이전 앱 실행 방법은 `AGENTS.md`의 '개발 환경'을 참고해 주세요.

## 1단계 화면과 Figma 조정

- 예시 식당은 Osteria La Solita Zuppa, 카테고리는 수프 4개·메인 3개·주류 6개예요. 초기 장바구니는 나 1개·미영님 2개예요. 환율은 예시로 1 EUR = 1,499원을 사용해요.
- 메뉴 담기·취소, 내 메뉴 수량, 선택 팁 10%, 합계를 연결했어요. 동반인 메뉴는 읽기만 가능해요. 주문 문장 만들기와 범위 밖 기능은 준비 중 안내를 보여 줘요.
- Figma 원본 사진·SVG는 `public/figma/`에 있어요. SVG 고유 크기를 유지해요. 실제 데이터 사진이 없는 메뉴는 “사진 준비 중”을 표시해요.
- Figma의 10~12px 글자는 DESIGN.md의 최소 13px로, 보조 회색은 secondary 토큰으로 맞췄어요. 20·22px 카드 안쪽 여백은 xl(24), 6·10·14·18·20·28px 간격은 역할에 맞는 spacing 토큰으로 맞췄어요. 28px 시트 모서리는 lg(24)로 바꿨어요.
- 홈의 배경 그라디언트, 촬영 데모의 갈색 테이블·크림 종이색은 토큰에 없는 값이라 쓰지 않았어요. 화면 배경은 단색이며 촬영 예시는 primary/surface를 사용해요. 기기 상태바·홈 인디케이터는 운영체제 영역이라 앱에 복제하지 않았어요.
- AI 장식은 gradient-ai 토큰을 사용해요. 1단계에서는 AI 설명임을 흉내 낸 예시 문구라는 점을 표시해요. 실제 분석으로 오인하지 않도록 출처 문구를 조정했어요.
- Figma의 메뉴 선택 상태와 장바구니 예시는 서로 달라 초기 상태를 장바구니 예시에 맞춰 통일했어요. 미영님 메뉴 EUR 28.00의 팁 포함 소계는 EUR 30.80으로 계산해요(Figma 표기 22.00 수정). 전체 EUR 41.80의 원화는 반올림해 62,658원으로 계산해요(Figma 표기 62,659원과 1원 차이).
- 장바구니의 결제 패널은 수량 조작을 막지 않는 고정 section으로 구성했어요. 별도 대화상자 성격의 직원 확인 문장은 BottomSheet를 재사용해요.

## 2단계 — Gemini 분석

- `api/analyze-menu.ts`의 POST 함수가 서버 환경의 `GEMINI_API_KEY`로 Gemini를 호출해요. 기본 모델은 `gemini-3.5-flash-lite`이며 `GEMINI_MODEL`로 바꿀 수 있어요. Google 직접 provider를 사용하므로 AI Gateway 키는 필요 없어요.
- 촬영 화면에서 사진 1~6장(각 10MB 이하)을 선택하고 “메뉴판 분석하기”를 누르세요. 브라우저에서 최대 변 1800px의 JPEG로 압축하며 전체 JSON을 3.9MB 이하로 제한해요. 서버는 4MB를 넘는 본문을 거부해요.
- 서버는 메뉴와 EUR 통화를 확인하고 구조화된 결과를 검증해요. 원문 가격을 읽지 못한 메뉴는 추정하지 않고 제외·안내하며, 여러 사진의 동일 이름·가격은 중복 제거해요. 다른 통화·판독 불가 사진·잘못된 응답은 분석 실패로 처리해요.
- 성공하면 식당명·카테고리·메뉴 목록을 교체하고 이전 예시 장바구니를 비워요. 실제 분석에서는 가짜 동반인 메뉴가 섞이지 않으며 팁은 기본 미선택이에요. 원화 환산에는 아직 예시 환율 1 EUR = 1,499원을 사용해요.
- 실패하면 예시 메뉴로 복귀하고 “분석에 실패했어요”를 계속 표시해요. “다시 촬영하기”로 재시도할 수 있어요. 분석 중 중복 요청을 막고 화면을 나가면 취소해요. 서버 호출은 65초, 클라이언트는 80초 제한이며 공급자 재시도는 자동으로 하지 않아요.
- AI가 추정한 음식 설명과 원문에서 읽은 재료·알레르기는 구분해요. 실제 원문 인식도 틀릴 수 있어 이름·가격·알레르기를 확인해 주세요.
- Places 키는 아직 사용하지 않아요. 실제 분석 메뉴는 식당 예시 사진을 임의로 붙이지 않고 “사진 준비 중”으로 표시해요. Places 연결은 키 준비 후 별도 진행해요.

Vercel에서는 프로젝트 최상위를 Root Directory로 사용하고 `src` 브랜치를 배포해요. `GEMINI_API_KEY`를 **Preview와 Production의 Secret**으로 등록한 뒤 새 배포를 만들어 주세요. 기존 고정 배포 URL에는 새 코드가 반영되지 않으므로 최신 Ready 배포 URL을 사용하세요. 필요할 때만 `GEMINI_MODEL`을 등록해요. 로컬 실행은 `.env.example`을 `.env.local`로 복사해 서버 키를 넣고 `npm run dev`를 실행하면 동일 API를 사용할 수 있어요. `.env.local`과 실제 키는 커밋하지 않아요. `VITE_*`에 키를 넣지 마세요.

검증은 공급자 응답을 대체한 테스트로 요청 검증·압축·성공/실패·취소·메뉴/장바구니 연결을 확인해요. 실제 Gemini 키와 프로젝트 할당량의 유효성은 Vercel에서 메뉴판을 촬영해 확인해야 해요.
