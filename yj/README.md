# meide 메뉴 주문 흐름 · 점검용 Android 파일

현재 메뉴판 분석·메뉴 담기·동반인 공유·영수증 기능의 0.1.3 빌드예요.

- [점검용 AAB](./meide-0.1.3-debug.aab): 번들 구조 확인용이에요.
- [휴대폰 설치용 APK](./meide-0.1.3-debug.apk): Android 폰에서 설치해 테스트할 수 있어요.
- [SHA-256 체크섬](./SHA256SUMS): 내려받은 파일을 확인할 수 있어요.

**이 AAB는 디버그 서명된 점검용 파일이므로 Google Play 제출용으로 사용할 수 없어요.** 정식 앱 ID와 업로드 서명을 설정한 release AAB가 필요해요. AAB는 휴대폰에서 직접 설치하는 파일이 아니에요. 지금 테스터에게 전달할 파일은 APK예요.

| 항목 | 값 |
| --- | --- |
| 버전 / 버전 코드 | 0.1.3 / 4 |
| 앱 ID | `app.meide.preview` |
| 최소 / 대상 Android API | 24 / 36 |
| 빌드 종류 | debug |
| 소스 브랜치 | `src` |
| 기준 소스 커밋 | `d9466d8ecae301d53321fa48cee217af59e437b5` |
| 앱 기능 코드 커밋 | `a1911092390836290220a6b8ef6069dee3b74bb9` |
| 연결 서버 | https://meide-meide1.vercel.app |
| 빌드 날짜 | 2026-11-16 (한국시간) |

APK 확장자를 바꾼 것이 아니라, 해당 APK와 같은 프로젝트·웹 자산으로 Gradle의 `:app:bundleDebug` 작업을 실행해 AAB를 만들었어요. APK와 AAB의 웹 자산 일치, AAB 구조, 앱 ID·버전, 디버그 서명을 확인했어요. 상세 확인 결과는 [build-info.json](./build-info.json)에 있어요.

`MJ` 폴더의 팀원 빌드와는 별개의 산출물이에요. 팀원의 앞부분과 통합한 최종 앱은 아직 아니에요.

## 설치·사용

APK 파일을 Android 폰에 내려받아 열고, 요청될 때 해당 설치 출처를 허용해 주세요. 같은 서명의 이전 점검용 앱에는 업데이트 설치할 수 있어요. 메뉴판 분석 후 장바구니에서 식사 인원과 여행 지역을 선택해요. 동반인도 같은 APK를 설치한 다음 새로 만든 초대 링크로 참여해요.

실제 API에 연결돼 있어요. Gemini의 앱 전체 하루 보호 한도는 50회이며 메뉴 분석·사진 검증·번역이 함께 사용해요. 한도는 한국시간 09:00에 새 날짜로 전환돼요. 사용자별 50회가 아니에요.

## Google Play 제출 전에 할 일

1. 팀원 코드와 화면·로그인·주문 흐름을 통합하고 최종 기기 점검을 진행해요.
2. 팀에서 정식 앱 ID를 확정하고 업로드 키로 release AAB를 서명해요.
3. Play 앱 서명 인증서와 앱 ID에 맞춰 초대 링크의 도메인 연결 정보를 갱신해요.
4. 스토어 등록 정보·개인정보처리방침·데이터 보안 항목을 준비해요.

서명 키·비밀번호·서버 API 비밀 키는 이 폴더에 포함하지 않아요.
