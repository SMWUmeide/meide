# 사용성 테스트 결과 분석 — 메뉴판 미식 가이드 앱

## 1. 테스트 개요

| 구분 | 세션 1 | 세션 2 |
|---|---|---|
| 일시 | 2026.10.11(일) 21:22 | 2026.10.12(월) 18:56 |
| 소요 시간 | 14분 15초 | 8분 45초 |
| 참여자 | 가족 3명 (참석자2·참석자3·민정) | 선생님 1명 (+ 지인 보조) |
| 주 조작자 | 참석자3 | 선생님 |
| 방식 | 영상 통화 + 모바일 프로토타입 직접 조작 | 영상 통화 + 모바일 프로토타입 직접 조작 |

**시나리오:** 이탈리아(로마) 여행 중 식당에 들어온 상황. 외국어 메뉴판을 촬영해 번역 → 메뉴 선택 → 주문 문장 만들기 → 직원에게 보여주기 → 주문 완료까지 진행.

메뉴판 이미지는 진행자가 카카오톡으로 공유했고, 참여자가 촬영하거나 저장 후 '사진 선택'으로 불러옴.

## 2. 잘 된 점 (두 세션 공통)

- **찍으면 바로 번역** — 두 세션 모두 진입이 어렵지 않았다고 평가. 세션 2 참여자는 별도 안내 없이 끝까지 스스로 진행함.
- **한글 + 현지어 병기 화면을 직원에게 보여주기** — "내가 말을 안 해도 돼"(세션 1, 민정). 독일 여행에서 메뉴를 몰라 곤란했던 실제 경험과 연결됨.
- **음식 사진** — 세션 1에서 가장 많이 칭찬받은 요소. 기존 메뉴판은 글과 가격만 있어 음식이 상상되지 않는다는 문제를 해결함.
- **원화 환율 표시** — 두 세션 모두 언급 (세션 1 08:33, 세션 2 07:20).
- **음식 설명, 발음 듣기, 동반인과 함께 고르기** — 세션 2 참여자가 기능을 바로 이해하고 사용함.

## 3. 발견된 문제점

| # | 문제 | 근거 | 심각도 |
|---|---|---|---|
| 1 | **메뉴 담기(+) 버튼을 찾지 못함** | 세션 1, 03:18 — "어디 있어, 보이지도 않아" → 뒤로 갔다가 다시 진입 | 높음 |
| 2 | **원본 메뉴판과 앱 결과의 대조가 어려움** | 세션 1, 12:48 — "이걸 맞춰봐야 되네, 다 나온 게 아니구나" | 높음 |
| 3 | **주문 완료 후 다음 행동이 불분명** | 세션 1, 04:36 "이게 끝인가 봐" / 세션 2, 04:20 "추가 주문은 홈으로 가야 하나요?" | 중간 |
| 4 | **앱의 기능 범위 오해** (결제·주문 전송 여부) | 세션 2, 04:09 — "결제도 이 앱으로 되나요?" / 세션 1, 00:15 — 앱 목적을 처음에 오해 | 중간 |
| 5 | **사진 출처에 대한 신뢰·저작권 우려** | 세션 1, 09:55~ — 구글 방문자 사진을 사업자가 써도 되는지 | 중간 |
| 6 | **실제 현지 메뉴판·다른 지역 지원 여부 의문** | 세션 2, 06:13 / 06:50 | 낮음 |

### 문제별 해석

1. **메뉴 담기 버튼** — 핵심 과업(메뉴 선택)에서 막힌 유일한 지점. 버튼의 크기·위치·대비를 우선 점검해야 함.
2. **원본과 결과 대조** — 프로토타입에 일부 메뉴만 들어간 탓도 있지만, 사용자가 실물 메뉴판과 앱 결과를 1:1로 맞춰 보려는 행동이 확인됨. 결과 화면에서 원본 메뉴판 위치를 알 수 있어야 한다는 근거가 됨.
3. **주문 완료 후 흐름** — 완료 후 아티클 화면으로 넘어가면서 '추가 주문'으로 돌아가는 경로가 보이지 않음.
4. **기능 범위** — 결제는 지원하지 않는다는 점, 주문은 식당으로 전송되지 않고 '보여주는' 방식이라는 점을 초반에 알려줄 필요가 있음.
5. **사진 신뢰** — 팀에서 고민 중인 AI·이미지 신뢰도 문제와 같은 맥락. 사진 출처 표기가 필요함.

## 4. 사용자 제안

- **메뉴 선택 전 별점·다른 사람 평가 탭** (세션 2) — 식사 후 남기는 '한국인 반응'을 메뉴 고르는 화면에서 바로 볼 수 있게 하면 이 요구를 충족할 수 있음.
- **제휴 식당 사진 활용** (세션 1) — 저작권 문제를 피하는 대안.
- **다른 지역 확장** (세션 2) — 유럽 외 중국·동남아 등.

## 6. 분석의 한계

- 진행자가 중간에 "메뉴를 골라주시면 돼요", "밑으로 내려보세요"처럼 **안내를 제공**해 자연스러운 탐색이 일부 영향을 받음.
- 세션 1은 여러 명이 함께 보며 진행해 **개인별 반응 구분이 어려움** (주 조작자는 1명).
- 메뉴판 사진을 카카오톡으로 받아 넣는 과정은 **테스트 환경의 문제**로, 앱 자체의 문제와 구분해야 함.
- 프로토타입에 **일부 메뉴만 구현**되어 있어 문제 #2에 영향을 줬을 수 있음.
- 음성 전사 특성상 일부 발화가 부정확하게 기록됨.
